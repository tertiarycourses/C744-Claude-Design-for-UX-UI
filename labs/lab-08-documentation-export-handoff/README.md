# Lab 8 — Documentation, Export and Handoff

Course: Claude Design for UX/UI (C744)
Duration: 25 minutes
Alignment: LO4

## Scenario

Prepare the final prototype for stakeholder review, developer handoff and end-user guidance.

## Goal

Create a versioned export bundle, decision log, handoff brief and task-based user guide.

## Files in this folder

- `CHANGELOG.md`
- `HANDOFF.md`
- `USER-GUIDE.md`
- `export-checklist.md`
- `prompt.txt`
- `Sample-Code.pdf` — printable mirror of the supplied prompts/code

## Detailed procedure

1. Open the supplied files in this folder and read the scenario, acceptance criteria and evidence checklist.
2. Sign in to Claude Design at https://claude.ai/design and create a project named for this lab.
3. Add the supplied prompt and any starter files listed below as project context.
4. Review the required output: versioned export bundle, decision log, handoff brief and task-based user guide.
5. Ask Claude to restate the user goal, constraints and missing information before generating.
6. Resolve any material gaps using the supplied evidence; do not invent sensitive or unsupported facts.
7. Generate the first version and inspect hierarchy, content coverage, states and system consistency.
8. Use chat for broad changes, inline comments for local issues and direct edits for deterministic text corrections.
9. Create a named version checkpoint before making the final evidence-led refinement.
10. Check every acceptance criterion and correct any failure before export.
11. Export or share the final design and capture the named evidence in this folder.
12. Complete the reflection: what changed, why it changed and what evidence supports the decision.

## Acceptance checklist

- [ ] Change log explains rationale
- [ ] Export matches downstream need
- [ ] Guide supports a real task
- [ ] Handoff includes states and acceptance

## Evidence to submit

- The named output or export.
- A Claude Design version checkpoint or share link.
- One screenshot showing the final relevant state.
- A short decision note identifying the evidence behind the final change.

## Reflection

1. Which assumption did you change after reviewing the design?
2. Which principle or metric guided the change?
3. What would you test next with a real user?
